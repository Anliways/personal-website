# 把工作流压到最简

效率系统的第一步不是「加工具」，而是「减环节」。过去一年我把自己的数字工作流重构了三轮，最终的结论非常朴素：**能被自动化的绝不手动，能被合并的绝不拆分。**

## 三个核心原则

1. **单一入口**：所有任务先进入同一个收件箱，再分发。
2. **默认无界面**：CLI 与快捷指令优先于图形界面，减少上下文切换。
3. **周回顾**：每周固定 30 分钟，砍掉连续两周没被用到的自动化步骤。

## 一个例子

以前发布一篇文章需要：写作 → 排版 → 上传 → 改链接 → 发通知，五个环节。现在是一条命令：

```bash
publish draft.md --to blog,telegram,rss
```

工具链本身不重要，重要的是**每个环节都值得被质疑**。

> 少即是多（Less, but better）不是口号，而是一种持续做减法的纪律。
